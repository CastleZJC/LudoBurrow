# 1. 文档概述

## 1.1 编写背景

LudoBurrow（ludo = 拉丁语「玩」+ burrow = 「洞穴、庇护所」）定位为 PC 端益智游戏平台，面向儿童与休闲玩家（教学/家庭场景友好）。设计于 2026-09-05 定稿（v1.0），本文为定稿后的正式架构说明。

**命名查重**：GitHub 全站 `LudoBurrow in:name` 零重名（2026-09-05 验证；曾拟名 LudoNest，因与活跃仓库 `Loenus/ludonest` 重名而弃用）。

## 1.2 文档目标

以精简口径向项目评审方说明：系统定位、总体架构、技术栈、模块划分、三游戏核心设计、平台通用能力、数据与资产、发布方案、里程碑与验收标准。

## 1.3 适用范围

- 项目评审与架构决策回顾
- 新成员/新 AI 会话快速理解系统全貌

# 2. 系统定位与建设原则

## 2.1 系统定位

PC 端益智游戏平台：内置三个游戏（各 50 关），免安装本地运行，同一构建产物可在线部署。

| 游戏 | 玩法核心 | 关卡 |
|---|---|---|
| 键盘按键 | 看字符按键：随机字母数字 / 英文单词 / 中文拼音 | 50 |
| 拼图 | 类线下拼图：切块、吸附、试错、校验 | 按专题方案动态 |
| 迷宫 | 方向键/WASD 控制像素小人走迷宫 | 50 |

## 2.2 建设范围

- **一期（M1-M6，本地优先）**：平台内核（注册表/关卡/计时/存档/设置）+ 三游戏全量 + 拼图切块引擎（本地算法 + 可选 AI 增强）+ 迷宫生成器与 8 主题瓦片皮肤（验收返工二轮补齐）+ **多语言中/英（个人设置切换）** + **内置图库齐备（每专题 ≥5 张开放许可：CC0 / CC-BY / CC BY-SA / 公有领域，逐张标注）** + PWA + 发布流水线。一期全部具体功能落地，不延后不跳过；Web 端以运行环境适配层保留框架（登录态 + 素材仓库抽象 + LocalAdapter 实现）
- **二期（框架一期预留）**：Web 端用户登录 + 自定义素材用户隔离（WebAdapter 对接服务端）；除登录与素材隔离外，Web 端与本地端完全一致；本地端永不需要登录

里程碑细节见 §11 与《LudoBurrow 开发计划文档》。

## 2.3 建设原则

| 原则 | 含义 |
|------|------|
| 免安装 | 本地双击 `index.html` 即玩（file:// 协议），本地优先 |
| 轻便 | 一期本地纯前端静态产物（无后端、无数据库）；二期 Web 端仅增加登录与素材隔离服务端 |
| 扩展性 | 游戏插件化（GameModule 统一接口），新增游戏零侵入 |
| 开源合规 | 内置图库全部 CC0/CC-BY；商业 IP 图片仅「自定义导入」本地加载，不分发、不出本机 |
| 双端一致 | Web 端除用户登录与自定义素材隔离外，与本地端完全一致（运行环境适配层预留，技术架构 §7.4） |
| 多语言 | UI 中/英双语，个人设置切换立即生效，框架可扩展；同功能同描述同出处（技术架构 §13.5） |

# 3. 总体架构设计

## 3.1 架构结论

**纯前端单页静态应用**（Vite + TypeScript + Vue 3 + Pinia + Canvas 2D），单文件 IIFE 构建产物 + 相对路径资产目录：

```
src/
├── core/                    # 平台内核（游戏无关）
│   ├── game-registry.ts     #   游戏注册表：GameModule 在此注册即接入
│   ├── level-manager.ts     #   50 关序列、顺序解锁
│   ├── timer.ts             #   正计时 + 可选上限（竞赛/防沉迷）
│   ├── save.ts              #   存档：localStorage + JSON 导入导出 + 版本迁移
│   └── settings.ts          #   全局设置（AI Provider 配置、限时策略）
├── games/                   # 游戏模块（插件式）
│   ├── keygame/  ├── jigsaw/  └── maze/
├── engines/                 # 可复用引擎（纯逻辑，无 UI，可单测）
│   ├── jigsaw-cutter/  ├── maze-generator/  └── wordbank/
├── components/              # 平台级 UI（主菜单/关卡选择/暂停/结算/设置）
├── assets/                  # 内置 CC0 图库（按专题分目录）、瓦片皮肤、sprite
├── ai/                      # AI Provider：Qwen/GLM 预设 + 自定义 OpenAI 兼容端点
├── i18n/                    # 多语言：zh-CN/en-US 语言包 + SUPPORTED_LOCALES 注册表
└── services/                # 运行环境适配层：登录态 + 自定义素材仓库（LocalAdapter 一期 / WebAdapter 二期）
```

**依赖方向**：`components / games → core`，`games → engines`，`components/games → services / i18n`；engines 与 core 不依赖 Vue，禁止反向依赖。

## 3.2 双模式运行形态

- **本地模式（主形态）**：`vite-plugin-singlefile` 产出单文件 IIFE `index.html`（JS/CSS 全内联），图片以相对路径放 `assets/` 随包分发——下载解压 → 双击 → 开玩
- **在线模式**：同一构建产物直接发布 GitHub Pages / Vercel / 内网静态服务器，零改动

## 3.3 核心使用场景

- **场景 A：本地即玩**——用户下载 Release zip 解压，双击 `index.html`，选游戏选关开玩；进度存 localStorage
- **场景 B：新游戏插件接入**——开发者新建 `games/xxx/` 实现 GameModule 接口并注册一行，计时/存档/关卡管理自动生效
- **场景 C：拼图自定义切块**——用户导入本地图片（FileReader，不出本机）→ 预切块调参/换种子/选算法/AI 建议 → 保存为独立版本方案 → 各方案进度互不干扰，可回滚
- **场景 D：AI 增强切块（可选）**——设置页配置 Qwen/GLM API Key，切块工作流调用视觉模型获取切割线建议，本地规范化后应用；失败/超时/未配置自动降级本地算法
- **场景 E（二期）：Web 登录与素材隔离**——Web 端登录后进入与本地一致的界面；自定义素材存服务端当前用户空间，用户间互不可见；本地端无登录直接玩、素材不隔离

# 4. 技术栈概览

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | Vite + TypeScript | 快、产物可控；`base:'./'` + IIFE 单文件输出兼容 file:// |
| UI 框架 | Vue 3 + Pinia | 生态最大、AI 辅助开发资料最全；Pinia 管平台级状态 |
| 国际化 | vue-i18n | 中/英双语，SUPPORTED_LOCALES 注册表扩展（技术架构 §13.5） |
| 渲染 | Canvas 2D（拼图/迷宫）+ DOM/CSS（键盘游戏） | 拼图任意形状切块与拖拽、迷宫瓦片渲染需要 Canvas 性能；键盘游戏是 UI 型，DOM 更简单 |
| 测试 | Vitest + @vue/test-utils | 与 Vite 同体系；覆盖率阈值硬约束 |
| AI（可选） | Qwen（DashScope）/ GLM（智谱）OpenAI 兼容接口 | 用户指定优先；国内可达、配置标准 |

> 精确版本于 M1 脚手架初始化时锁定，钉版清单以《LudoBurrow 代码规范》§十三 为准。

# 5. 模块化架构与核心能力

## 5.1 GameModule 插件接口（扩展性核心）

```ts
interface GameModule {
  id: string                    // 'jigsaw'
  name: string                  // 显示名
  icon: string
  createLevel(n: number): LevelConfig   // 第 n 关配置（确定性：参数+种子）
  mount(container: HTMLElement, level: LevelConfig, hooks: GameHooks): GameInstance
}
```

## 5.2 数据流

```
LevelConfig(参数+种子，确定性生成)
   → GameInstance 挂载渲染
   → 用户操作（按键/拖拽/移动）
   → 完成/放弃 → 结算（用时、星级）
   → save 写入 → 解锁下一关
```

所有关卡由**参数 + 种子程序化生成**（mulberry32 PRNG），无手工配置的 150 个关卡文件；同关卡每次打开内容一致（可复现、可分享「第 37 关」这样的引用）。

## 5.3 核心能力一览

| 能力 | 要点 |
|---|---|
| 键盘按键游戏 | 四模式（大键盘随机字母数字 / 小键盘随机字母数字 / 英文固定单词 / 中文拼音）；虚拟键盘可视化 + 实时反馈（对绿错红抖动）；50 关难度曲线 |
| 拼图游戏 | 五区布局（效果图/拼图区/暂存区/当前块/剩余块）；网格级吸附、三区全空校验、放弃分步演示、帮助计次；均匀网格（内容只定块数，验收返工二轮）+ 锯齿凸凹切块 + 块唯一性校验；方案版本与进度隔离 |
| 迷宫游戏 | 种子递归回溯生成 + 分支度参数；瓦片主题制（8 主题：城堡/花园/雪原/火山/海底/丛林/太空站/矿洞）；像素小人四方向帧动画；方向键/WASD |
| 平台通用 | 正计时 + 竞赛/防沉迷两种限时语义；localStorage 存档（schema version + 迁移链 + JSON 导入导出）；每游戏 50 关顺序解锁 |
| 多语言 | UI 中/英双语，个人设置切换立即生效；游戏内容不随语言切换；翻译齐备发布门禁 |
| 运行环境适配 | 登录态 + 自定义素材仓库经 services/ 适配层（本地 IndexedDB 持久化 / Web 二期按用户隔离） |

各游戏与切块引擎的详细设计（切块算法目标、AI 增强链路、放弃演示顺序等）见《技术架构说明文档》§10-§12。

# 6. 平台通用功能

- **计时与限时**：每关正计时（结算是核心成绩指标）；可选上限时间，竞赛模式到时立即结算、防沉迷模式到时提醒可锁定（家长设置）
- **存档（core/save.ts）**：localStorage 单一 key `ludoburrow/save`，带 schema version；导出/导入 JSON；内容含各游戏进度与最佳成绩、解锁状态、全局设置、AI 配置、拼图切块方案（含各自进度）；写入前校验 + 旧版本迁移链，损坏不静默清空
- **关卡管理**：每游戏 50 关顺序解锁（第 n 关过解锁第 n+1）；关卡选择页显示星级/最佳用时
- **多语言（i18n）**：UI 中/英双语，个人设置切换立即生效；zh-CN/en-US 键位 1:1，同功能同描述同出处；发布前翻译齐备校验强制（详见技术架构 §13.5）
- **页面范围**：主菜单 / 关卡选择 / 游戏页（三游戏）/ 暂停 / 结算 / 设置 / 图片管理（拼图切块工作流）

# 7. 数据与资产

| 资产 | 形态 | 说明 |
|---|---|---|
| 关卡定义 | TS 模块（内嵌） | `createLevel(n)` 参数化生成，规避 file:// 下 fetch JSON 的 CORS 限制 |
| 英文词库 | TS 模块 | 分级词表（3 字母 → 8+ 字母），来源开源词表整理 |

# 8. 发布方案

- **发布产物形态**：`LudoBurrow-vX.Y.Z/`（单文件 `index.html` + `assets/images/` 等），打包为 zip 附 GitHub Release
- **发布流水线**：`npm run release` = 类型检查 → 全量测试 → 覆盖率达标（≥80% 硬门槛）→ **翻译齐备校验** → 构建 → 产物校验；不允许带错误发布
- **在线部署**：同一产物发布 GitHub Pages / Vercel / 内网静态服务器，零改动；PWA（Service Worker 缓存）已落地（M6.2）——在线版访问一次后离线可玩，实施细节见《LudoBurrow 部署规范》§5.3
- 详见《LudoBurrow 部署规范》

# 9. 兼容性风险与前置验证

| 风险 | 对策 |
|---|---|
| file:// 各浏览器行为差异 | M1 即建立浏览器矩阵冒烟（Chrome/Edge/Firefox） |
| 1K 图片本地包体积大 | 内置图库程序化生成（体积可控可复现，M3.9/M6.1 实施口径见技术架构 §15.3，24 张约 870KB 全量随包）+ 在线版 SW 按需缓存（部署规范 §5.3） |
| 切块算法产生歧义块 | 块唯一性评分（颜色方差/边缘特征）低于阈值的规格被优选/建议链路抑制（验收返工二轮起切割恒均匀，不再挪线）；AI 建议同样过此校验 |
| 视觉 AI 返回不合法切割建议 | Provider 输出统一走本地规范化器（schema 校验 + 合法化），无效则降级 |
| 一期框架预留不足致二期 Web 大改 | 登录/素材分叉点一期收拢 services/ 适配层并以 LocalAdapter 全量验证抽象 |
| 翻译漂移 / 口径不一 | 同功能同描述同出处 + 守卫测试 + 发布翻译齐备门禁 |

# 10. 质量与测试基线

- **框架**：Vitest + @vue/test-utils；`tests/` 独立目录，与 `src/` 分离
- **重点**：engines（切块算法、迷宫生成可复现性、词库）与 core（timer、save 迁移、level-manager）单测；游戏组件交互级组件测试；Canvas 渲染逻辑抽纯函数保证可测
- **覆盖率**：80% 硬门槛（发布脚本强制不达标即失败），目标 90%；engines ≥90%、core ≥85%
- **翻译齐备**：i18n 守卫（键位 1:1 / 空值 / 注册一致 / 重复键）+ `npm run check:i18n`，与覆盖率并列发布双门禁
- 详见《LudoBurrow 测试规范文档》

# 12. 非功能性要求

| 维度 | 要求 |
|---|---|
| 性能 | 拼图拖拽与迷宫渲染流畅（目标 60fps 交互）；本地包解压即用 |
| 包体积 | 核心 zip 控制在合理范围（图库程序化生成体积恒定 + 分专题包） |
| 可靠性 | 存档损坏可提示恢复；AI 失败自动降级，功能不中断 |
| 可维护性 | engines 纯逻辑可单测；新游戏零侵入接入 |
| 隐私 | 用户图片与 AI Key 仅存本机，无网络上传（AI 调用除外，仅发切块建议所需数据） |

# 13. 开源合规结论

# 14. 架构总结

LudoBurrow 以「纯前端静态单页 + 插件化游戏模块 + 确定性关卡生成」三根支柱满足免安装、轻便、可扩展三大核心约束；file:// 单文件构建保证本地双击即玩；切块引擎以「线条颜色关联 + 块唯一性校验」逼近线下拼图品质，AI 增强全程可降级；开源合规边界清晰（CC0/CC-BY 内置 + 商业 IP 仅本地导入）。本地/Web 双端分叉点（登录态、自定义素材）一期收拢到运行环境适配层，二期 Web 接入零改业务代码；多语言中英与翻译齐备门禁保障双语文本口径与开发口碑。
